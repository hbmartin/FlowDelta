# 0.3.1 review fixes

Date: 2026-11-27

FlowDelta 0.3.1 fixes the defects found in the review of PR #4 after 0.3.0 was tagged. The 0.3.0 tag (`9927235`) stays where it is; GitX pins 0.3.1 instead. The public API is unchanged, except that several existing values now describe what is on screen more strictly (see "Behavior hosts can observe").

## Fixes

### Noise

- JavaScript and TypeScript `this.` is no longer optional syntax: `this.reset()` and `reset()` call different functions. Python `self.` stays required as before.
- A comma that changes a value is never optional. This covers one-element tuples (Python `(value,)`, tuple patterns and subscripts) and array holes, where the previous token is `(`, `[`, `{` or `,`.
- String, template, regex and rune literals compare as one exact token, so a change inside quotes is never formatting or optional syntax.
- Structural digests keep the exact text of named leaves such as string contents. Only anonymous leaves are trimmed.

### Data flow (Python and Go)

- Python `global` and `nonlocal` statements inside a nested function or class no longer hide the enclosing function's own definitions.
- A Python annotation without a value, such as `x: int`, defines nothing.
- A Python lambda's defaults and a comprehension's first iterable are read in the enclosing scope, and an assignment expression inside a comprehension binds in the enclosing function.
- A bare Go `return` reads the named results, which entities now carry as `SourceEntity.resultNames`.
- Go map literal keys are read. Struct field labels are still not variables.
- An assignment reads its value before it writes its target. A closure captures uses that come before a local definition, so `x := x + 1` in a Go function literal reads the outer `x`.
- Without syntax metadata, Go parameter names follow Go's names-before-types rule.

### Concern grouping, triage and walkthrough

- A rename or move is refactoring only while both the body and the parameter clause stay the same. A change to a default value or a parameter type is behavioral.
- Grouped triage lists changes that no concern holds as "Other Changes". "Unchanged" now holds only unchanged entities.
- Walkthrough narration fences each label with more backticks than any run inside it, so Markdown keeps the whole label as code.

### Git

- Cancelling a comparison terminates git even after git has closed its output. Error output drains on another thread, so git cannot stall writing more than a pipe buffer holds.

### Review view

- A report with no entities clears the previous function's graph, source and selection.
- The walkthrough ends when a function outside its current step is chosen, or when grouping changes the order. A walkthrough move is reported once, after its step is on screen.
- A removed call node shows the base source.
- Before / After keeps one selection across its two graphs and reports a selection in the target graph.
- A graph that gets focus after its selected node has left the layout selects a node that is still visible.

## Behavior hosts can observe

- `FlowReviewState.slice` and `FlowDeltaReviewView.sliceDirection` are `nil` unless a slice is drawn: in the delta graph, from a selected node. `setSlice(_:)` leaves Slice off outside the delta graph. A host that applies a saved slice before a node is selected reads `nil` until one is.
- `FlowReviewState.selectedNodeStableID` names the target graph's node when the selection is there.
- `FlowTriage.sections` can return an "Other Changes" section.
- `FlowDeltaReviewViewDelegate` gets one `.user` change per walkthrough move instead of one per internal update.

## Validation

Result: **FlowDelta 0.3.1 gate passed** on the committed candidate `5c5d723` (fixes `5da4d88`..`2cacb29`, version `bfc60bd`, coverage ratchet `5c5d723`) on `codex/m2-closeout-m3`.

- Each fix started as a failing XCTest that passed after the change. Each fix's commit names its tests.
- Debug: `swift test` passed all 163 XCTest cases, up from 145 in 0.3.0.
- Release: `swift test -c release` passed all 163 cases, and `swift build -c release` passed.
- Extension: `swift test --package-path Extensions/FlowDeltaIndexStore` passed all 5 cases, and its release build passed.
- Coverage: the Xcode result bundle passed `scripts/check_coverage.py` at **95.49% across 58 library files**, up from 95.12%. `--record-improvements` raised the overall floor and the `GitCLIRevisionProvider.swift` (98.48%) and `FlowDeltaReviewView.swift` (98.53%) floors.
- Style: pinned SwiftFormat lint and pinned SwiftLint strict passed with no violations.
- Native UI: the reference snapshot passed unchanged, because none of the fixes changes the default layout. The new review tests cover:
  - an empty report;
  - leaving a walkthrough step, regrouping, and a delegate that ends the walkthrough;
  - removed call sources;
  - the drawn slice;
  - Before / After selection;
  - graph focus.
- CLI: the release `flowdelta` reports 0.3.1. A 48-run smoke matrix exited 0 and produced output for every run, and every JSON output parsed. It covered:
  - all four formats;
  - four flag sets: none, `--noise hide-cosmetic`, `--group-by-concern --walkthrough`, and all three together;
  - real Swift history (`d4ac844..0722fea`, and this release's own fixes `9927235..2cacb29`);
  - real Python history (a GitX boundary-checker revision).
- Consumer: a clean executable package resolved FlowDelta through `file:///Volumes/Pro2T/FlowDelta` at exact version 0.3.1. It linked Core, Analysis, Git, Export, Layout and UI, then built and ran, printing the noise policies, the export options and a fresh review view's state.
